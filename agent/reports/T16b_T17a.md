# T16b 주소 대체 보강 + T17a 상황판 저장 기반

## 결과

- T16b: V-World 주소가 비었을 때 주소를 `500m 이내 가장 가까운 DB 도움처 → 1km 이내 같은 구 대표 지점 → 부산 {구}` 순으로 정한다. 도움처 조회는 응답 목록과 무관하게 기존 bbox 리포지토리 메서드를 사용하고 모든 `PlaceKind`를 대상으로 한다. 반경은 `messages.json`의 `_addressFallback` 설정에 있다.
- T17a: `dashboard.json`, V34 마이그레이션, 격자·동 코드 변환, 이벤트/전화 저장소·기록기·퍼저를 추가했다. 기록기는 원문·정밀 좌표·주소를 받거나 저장하지 않으며, 슬롯은 허용된 키와 대문자 코드만 남긴다. 전화 이벤트는 112·119·1330만 저장한다.
- 상황판 기록기와 API-E08은 이번 단계에서 `EmergencyService`에 연결하지 않았다.

## 실서버 및 DB 확인

- 포트 8081에서 해운대 좌표 요청 응답: 유형 `URGENT`, 연락처 `119`, 응급실 병상 `3`, 메시지 `null`, 진료불가 `false`; 카드 주소는 `부산 해운대구 해운대 관광안내소 근처`였다.
- 광안리 요청 응답 카드 주소는 `부산광역시 수영구 광안동 1306-2`였다.
- DB의 `flyway_schema_history`에서 V34 적용을 확인했고 `emergency_event`, `call_event` 열을 조회해 정밀 좌표·주소·문장 열이 없음을 확인했다.
- 로컬 DB에는 V33 적용 기록이 있었지만 이 worktree에 V33 마이그레이션 파일이 없어 기본 기동은 Flyway 검증에서 실패했다. V33이나 공용 설정은 수정하지 않고, 로컬 확인 실행에만 `--spring.flyway.ignore-migration-patterns=*:missing`을 전달해 V34 적용과 서버 기동을 검증했다.
